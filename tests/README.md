# Testing Strategy

This document describes the testing strategy for verifying artifacts generated by the Xeokit Data Engine API samples.

## Overview

The test suite uses **Golden File Testing** (also known as Snapshot Testing) to validate that sample scripts generate correct artifacts. Golden files are pre-generated reference artifacts stored in `tests/fixtures/golden/` that serve as the baseline for comparison.

## Test Structure

```
tests/
├── integration/           # Integration tests for each sample
│   ├── convertIfc2Xkt.test.ts
│   ├── convertRvt2Glb.test.ts
│   ├── getSchemas.test.ts
│   └── checkJobPayload.test.ts
├── fixtures/
│   └── golden/           # Golden reference artifacts
│       ├── convertIfc2Xkt/
│       ├── convertRvt2Glb/
│       ├── getSchemas/
│       └── checkJobPayload/
└── utils/                # Reusable test utilities
    ├── validators.ts     # Validation functions
    └── comparators.ts    # File comparison utilities
```

## Testing Approach

### 1. Golden File Testing

Each test compares newly generated artifacts against golden reference files:

- **File presence**: Verifies all expected files exist
- **File sizes**: Validates sizes are within acceptable tolerance (±5-10%)
- **File structure**: Validates binary headers (GLB, XKT) and JSON schemas
- **Directory contents**: Ensures correct file sets are generated

### 2. Validation Types

#### Binary File Validation (GLB, XKT)

- Header validation (magic numbers, version checks)
- Minimum file size checks
- Size comparison against golden files

#### JSON File Validation

- Parse validation
- Schema structure validation
- Semantic comparison (excluding dynamic fields like timestamps)

#### Event/Webhook Validation

- Event structure and required fields
- Chronological ordering
- Event type sequences (started → succeeded/failed)

### 3. Test Categories

#### Integration Tests

Full end-to-end validation of sample outputs against golden artifacts.

#### Structural Tests

Validate that generated artifacts have correct structure and format.

#### Comparative Tests

Compare generated artifacts against golden baselines with tolerance thresholds.

## Test Files

### `convertIfc2Xkt.test.ts`

Tests IFC → GLB → XKT conversion workflow:

- GLB output validation (Duplex.glb)
- Metadata JSON (Duplex.json)
- Manifest JSON (Duplex.manifest.json)
- XKT output validation (Duplex.xkt)
- Job state structure and success status
- Task execution validation
- Directory content verification

### `convertRvt2Glb.test.ts`

Tests RVT → GLB conversion with webhook monitoring:

- GLB output validation (container.glb)
- Metadata JSON (container.json)
- Webhook event structure
- Event chronological ordering
- Event sequence validation (started → completion)

### `getSchemas.test.ts`

Tests schema generation and export:

- JSON Schema files (Job.json, JobState.json, Event.json)
- TypeScript definition files
- Quicktype-generated TypeScript files
- Schema content validation ($schema property)
- Export statements in TypeScript files

### `checkJobPayload.test.ts`

Tests payload validation functionality:

- Payload structure validation
- Valid operation types
- Expected API response formats
- Error handling structures

## Utilities

### `validators.ts`

Reusable validation functions:

- `validateJobState()` - Validates JobState objects
- `validateEvent()` - Validates webhook events
- `validateFileExists()` - Checks file existence
- `validateFileSize()` - Validates minimum file sizes
- `validateGlbHeader()` - GLB binary format validation
- `validateXktHeader()` - XKT binary format validation
- `validateJsonFile()` - JSON parsing and validation
- `validateChronologicalOrder()` - Timestamp ordering

### `comparators.ts`

File comparison utilities:

- `compareFileSizes()` - Size comparison with tolerance
- `compareFileChecksums()` - Exact binary comparison
- `compareJsonFiles()` - Semantic JSON comparison
- `compareDirectoryContents()` - Directory file listing comparison
- `computeFileChecksum()` - SHA256 hash computation

## Golden Artifact Management

### Generating Golden Files

Golden files are created by running the samples once with known-good configuration:

```bash
# Run all samples to generate outputs
pnpm sample:getSchemas
pnpm sample:convertIfc2Xkt
pnpm sample:convertRvt2Glb
pnpm sample:checkJobPayload

# Copy outputs to golden fixtures
cp -r .sample-outputs/* tests/fixtures/golden/
```

### Updating Golden Files

When intentional changes are made to the API or sample scripts:

1. Verify the new outputs are correct
2. Update golden files:
   ```bash
   rm -rf tests/fixtures/golden/*
   cp -r .sample-outputs/* tests/fixtures/golden/
   ```
3. Re-run tests to ensure they pass:
   ```bash
   pnpm test
   ```

### Golden File Storage

Golden files are committed to version control:

- Binary artifacts (GLB, XKT) - compressed efficiently by Git
- JSON files - diffable and reviewable
- TypeScript files - diffable and reviewable
- Webhook event files - JSON format

## Tolerance Thresholds

Different artifact types have different comparison tolerances:

| Artifact Type    | Tolerance | Reason                                   |
| ---------------- | --------- | ---------------------------------------- |
| GLB files        | ±5%       | Binary formats may have minor variations |
| XKT files        | ±5%       | Binary formats may have minor variations |
| JSON metadata    | ±10%      | Metadata can vary slightly in structure  |
| JSON schemas     | ±10%      | Schema formatting may differ             |
| TypeScript files | ±10%      | Generated code formatting may vary       |

## Troubleshooting

### Test Failures

**File size mismatch:**

- Check if API output has legitimately changed
- Verify tolerance thresholds are appropriate
- Update golden files if change is intentional

**Missing files:**

- Ensure samples ran successfully
- Check sample output directories
- Verify golden files exist

**Invalid file structure:**

- Check binary file headers
- Validate JSON syntax
- Review API response format changes

### Re-generating Golden Files

If many tests fail after API changes:

```bash
# Clean old outputs
rm -rf .sample-outputs/*

# Run samples fresh
pnpm sample:checkJobPayload
pnpm sample:getSchemas
pnpm sample:convertIfc2Xkt
pnpm sample:convertRvt2Glb

# Update golden files
rm -rf tests/fixtures/golden/*
cp -r .sample-outputs/* tests/fixtures/golden/

# Verify tests pass
pnpm test
```

## Best Practices

1. **Run samples before testing** - Ensure `.sample-outputs/` is populated
2. **Review golden file changes** - Use Git diff to verify updates
3. **Use appropriate tolerances** - Binary files need more tolerance than JSON
4. **Document intentional changes** - Update test expectations when API changes
5. **Keep golden files up-to-date** - Sync with API version changes
6. **Test in CI/CD** - Automate testing in your pipeline
